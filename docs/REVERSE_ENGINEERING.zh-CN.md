# SFM 逆向全过程：从运行原游戏到家—街区恢复

整理于 2026-10-25，北京时间。本文根据可见用户对话、本地 Git 历史、运行收据和当前源码整理。它覆盖工作阶段、路线调整、失败与验收边界；不是完整逐调用日志。私有日志、存档和游戏资源不公开。

## 1. 先确定目标和证据来源

最初请求是拉取 [morluto/rea](https://github.com/morluto/rea)，配置环境并逆向 SFM，最终恢复代码和资源、运行起来。随后用户把近期验收收敛为最小可运行 MVP，再明确为完整的“家—街区”流程。

原程序是 Windows x64 Unity IL2CPP 游戏，Unity 版本为 `2022.3.62f2`。分析基线：

| 文件 | SHA-256 |
| --- | --- |
| GameAssembly.dll | `6003033049ac32e8712dc4101382534e21d65b97100c167ebec6bbca1462c18d` |
| global-metadata.dat | `457203754abe77b346fd98086a5c787bd41088d808cc81b1d4e2cae5b85c72c8` |

BepInEx 的 interop/DummyDll 只能提供类型和调用签名，不能把其中的包装或空方法说成游戏源码。实际方法体需要结合 REA/Ghidra 导出、机器码、IL2CPP metadata、字段偏移、RVA、资源序列化引用和原游戏行为逐步恢复。

最新 REA metadata 链接得到 10,508 个类型、79,095 个方法条目，其中 70,948 个有静态代码地址、8,147 个为空指针槽。这是整个 metadata 范围，包含依赖，**不是已经恢复的游戏方法数量**。静态地址存在也不代表行为已经验证。

## 2. 跑通原程序，建立对照

最早先启动原游戏并确认 BepInEx 初始化，再用有时限的只读探针记录活动场景、对象和帧号。初期证据只到标题场景，不声称可以正常游玩。

已有 BepInEx 导出工具被复用，用于定位必要模型、材质、动画与音频。用户后来明确要求停止无目的扩大资源覆盖，因此后续提取围绕实际玩法缺口进行，不反复导出整个游戏。原版、启用输入兼容或模组的原版、独立重建 Player 分开记录。

原版录制也遇到了真实限制：独占全屏抓图超时、自动键盘输入不生效、返回键不兼容。用户协助切窗口、开菜单和修改返回键。这些属于人工环境协助，不是代码实现；它们也说明项目并非完全无人值守。

## 3. 解决 Unity 环境，先产生真正的 Player

Unity 国际版下载遇到重定向、Hub 登录和许可证问题。下载与安装、命令行构建环境由 Agent 处理；用户最终完成本人账号登录/授权。

2026-10-13 至 10-14 的本地历史记录了全球版 runtime、编辑器下载和首个实际 Editor MVP 构建。早期 MVP 证明“独立构建能够执行”，不等于恢复了原版全部流程。

之后建立命令行构建、隔离测试档、运行观测、输入驱动和报告工具。遵循用户提供的 [AI harness 工程文章](https://kylekukshtel.com/ai-harness-engineering-game-development-claude-code)方向，将环境做成能反复构建、运行、观察、定位失败的工作台，而不是只追求一次编译通过。该链接是用户给出的工作流参考；本文不把它当作 SFM 行为证据。

## 4. 将恢复重点转向系统联动

用户反复强调：只从家里走出去再回来不算完成。随后将系统模型固定下来：

1. 家里准备：购买、装备、外形、技能、保存。
2. 街区风险：移动与动作、衣物当前状态、NPC 感知。
3. 任务达成：读取实际行为条件、累计进度、奖励结算。
4. 被发现的后果：原判定、生命与惩罚、失败界面、返回和临时状态清理。
5. 长期状态：货币、所有权、装备、外形、成长跨场景和重启保持一致。

恢复时区分物品所有权、实际装备和局内衣物状态；区分永久 RP、当局收益与失败损失。单独调用奖励函数、强改条件或看见 UI，都不能替代完整游玩证据。

代码修改按小步进行：给目标二进制和方法定位 → 对照原生分支与字段 → 写 C# 候选 → 编译 → 严格审计实际 Unity 程序集 → 运行原输入流程 → 核对前后状态与画面 → 留收据、提交和回退入口。空函数、推测和工具超时一直保留未完成标记。

## 5. 移动、输入与 NPC 失败链

菜单能点不代表角色能走。用户专门要求实测长按走、Shift 跑、释放停。恢复与验证涉及原 InputSystem 绑定生命周期、输入状态、动画/地面回调、相机和菜单互斥。

后续 Player 通过实际位移验证走跑停，用户也反馈“走、跑、停都正常”。NPC 则继续核对感知、发现、生命变化、失败后的返家和移动恢复，不能把距离触发或一次疑心上升写成失败验收完成。

实际失败链曾暴露退出场景后残留声音监听器等错误，按原生销毁/注销语义修复。测试失败也被保留：寻路预算用尽、条件未达成、相机遮挡、输入没有送到 UI，都记录真实失败，不把测试改成直接强写通关状态。

## 6. 购物、外形、任务、姿势和保存连接起来

早期购物与装备先验证少量类别，随后转向原 UI 输入路径、购买扣款、实际穿戴、外形调整、保存与冷启动。

2026-10-23 的已保留收据中，有可复核的局部连续流程：

| 收据/版本 | 实际记录的范围 | 边界 |
| --- | --- | --- |
| `home-preparation-player-v6` | 原 UI 购买、装备、外形输入、保存和冷启动 | 不代表所有物品/外形组合 |
| `home-prepared-loop-player-v4` | 任务 100000，永久 RP 30→40，经验 90→100；非零当局收益下 NPC 失败、返家、保存与冷启动 | 准备阶段证据继承，非当前版本全部重跑 |
| `home-post-pose-core-player-v1` | 学习姿势后的角色再次通过任务和 NPC 失败回归；任务奖励 10 RP；失败后返家移动、释放停止 | 完整渲染和全面流程标记仍为 false |
| `home-body-preview-margin-player-v2` | 站立、跪姿、抬腿、返回站立的 Body 预览取景，姿势切换和取消后的控制连续性 | 更广泛动画/穿模仍未完整验收 |

上述数字来自隔离测试角色的运行收据，不是公开用户存档。公开代码含相应观察器，收据摘要和原文件 hash 在 [evidence-index.json](evidence-index.json) 中。原始大日志及图片未随本次资源排除发布。

## 7. 空间治理和回退也成为开发约束

本地工程一度有大量重复源码、资源、缓存和 Player。用户要求迁移到 LayerFS，并先在新上下文启动验证，再清理旧重复内容。

用户提供的迁移实测为：逻辑内容 408.33 GB，单份 Store 33.14 GB，2,827,500 级别文件逐项校验；这是当时报告的口径，不是本次重新测量。后续不再把逻辑文件大小、Store 新增字节、解压缓存和 Windows 磁盘净回收混在一起。

权威源码留在 LayerFS。Unity 因挂载的大小写行为使用一套原生镜像；只保留一个原生 Player，历史构建以原始目录归档去重。删除前检查进程、路径边界、文件清单与 hash、检查点和读回结果，存档与不可再生资源不参加构建清理。

截至本次导出基线，本地研究 Git 历史有 **425 个提交**。公开仓库没有推送含资源的本地历史，而是保留原公开仓库历史，新增纯代码快照。小步 commit、LayerFS 检查点与外部增量 bundle 分别承担源码回退、文件状态和仓库备份职责。

## 8. 用户试玩反馈推动 UI、声音与渲染修复

用户整体试玩认可了基本系统，随后指出白底白字、主角问号、NPC 发现条缺失和声音/音乐不齐。最新一轮据此调整菜单对比度，恢复 NPC UI 更新和 BGM 生命周期代码。

`home-street-feedback-v3` 的实际 Player 已供手动试玩。旧自动观测确认家中 BGM 播放推进且音频采样非零，但这不代表全部音乐/音效正确。自动六面板测试出现独立 UI action asset 读实体鼠标、而角色读测试键鼠的冲突；设备路由候选已经编译，但本次公开的主源码仍是已集成 v3，没有把未运行验收的 v4 替换进去。

人物偏暗也没有用“整体调亮”草率处理。现有头发和风衣的材质/主贴图与原版导出一致，当前色彩空间是 Linear；下一步应比较角色实际插值光照探针、有效材质输入和原始预览 RT。街区 `Corevale_SwapLightmap` 仍有空方法，是独立恢复缺口，尚不能据此解释家中偏暗。

2026-10-25 还处理了一次 LayerFS 停止沙箱的恢复：先保存停止 overlay，再恢复已提交分支；未提交收据作为隔离候选提取并保留出处。没有把未校验的恢复文件冒充新验收结果。

## 当前状态与剩余工作

已有可玩的本地阶段成果；当前公开的是其代码，不是资源齐全的发行版。当前仍需：

- 完成最新构建的装备、任务、任务进度、PC/商店 UI 可读性与真实输入回归。
- 在街区实际确认 NPC 发现条和角色提示图标的条件、位置及变化。
- 对照原版补全音效、BGM 和场景声音的时序、音量及停止/切换行为。
- 恢复并验证街区光照切换，定位人物偏暗，继续检查相机、材质和 Shader。
- 扩大动画、动作打断、外形与衣物适配的实际画面覆盖。
- 在同一新版本、同一隔离角色上完成准备→任务结算→保存冷启动及 NPC 失败→返家→恢复控制的连续验收，补齐原版对照录制。

“有源码”“能编译”“Player 能启动”“某分支通过”“完整还原”是五个不同结论。当前达到前四项的不同范围，尚未达到第五项。
