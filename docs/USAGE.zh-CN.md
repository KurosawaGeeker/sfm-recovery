# Token、时间与费用口径

统计截止 **2026-10-25 16:27:03 北京时间**，在本次发布请求到来时冻结；不包含随后整理文档和上传的用量。数据与复算方法见 [usage-summary.json](usage-summary.json) 和 [summarize-usage.py](../tools/summarize-usage.py)。

## 可核实的本地用量

从本机可获得的主会话和 33 个后代子会话读取 `token_usage_record`，以明确的 `parent_thread_id` 选择任务树，只计各文件自己的 thread 记录，以 `(thread_id, response_id)` 去重。没有把每次出现的累计计数再相加，也没有把继承的父会话历史重复算进子会话。

34 个会话都有逐响应 ledger，34 个合计均与各自最后一个 ledger 的线程累计数相符。总计 **5,217,445,090 token（约 52.17 亿）**：

| 类别 | Token |
| --- | ---: |
| 输入（含缓存） | 5,192,615,102 |
| 其中：缓存输入 | 5,111,252,480 |
| 非缓存输入 | 81,362,622 |
| 输出（含推理） | 24,829,988 |
| 其中：推理输出 | 7,960,343 |
| 输入 + 输出 | 5,217,445,090 |

缓存输入占全部输入约 **98.43%**。非缓存输入加输出为 **106,192,610（约 1.06 亿）**。后一项不是官方独立计费单位，也不能把缓存当免费；它只是帮助理解大量重复上下文之外的量级。

这不是 52 亿字的代码或回答：长会话、工具结果、历史上下文在很多请求中重复进入输入。缓存输入已在 input 内，推理输出已在 output 内，二者不能再次加到总量。官方说明同样区分这些包含关系，并明确 usage 不是最终账单。[OpenAI 用量说明](https://developers.openai.com/api/docs/guides/agents-api/observability)

### 为什么与任务面板/旧统计不同

此次读取到的后期目标面板为 **23,150,204 token**、累计计时 **88,086 秒（24 小时 28 分 6 秒）**。这个目标创建得较晚，统计范围/定义也不同，不能当作从项目开始的总 token 或总工时，不能与上述 ledger 再相加。

另外，主会话旧式 `event_msg.token_count` 的最后一个 total 为 **1,917,766,139**，与逐响应 ledger 的 **1,949,201,044** 不一致。报告保留两者，不隐藏差异；主表使用能逐条累加且与 `thread_token_usage` 对上的 ledger。没有账单对账前，不将任一计数称为最终实际收费量。

## 大概值多少美元

**真实账单未知。** 项目通过 Codex 运行，没有取得对应逐请求账单、订阅分摊或历史服务档位。

仅作可复算的价格参考：假设所有已记录 token 都按 2026-10-25 查询的 OpenAI **Standard / Short** API 单价计算，且按上面的模型归属、无额外缓存写费，则约 **$3,347.28**；其中 Astra 约 $2,786.77，Sol 约 $560.51。这个数字不是实际花费。

每百万 token 的假设单价：Astra 普通输入 $10、缓存输入 $1、输出 $50；Sol 分别 $2、$0.10、$10。公式为 `非缓存输入 × 输入价 + 缓存输入 × 缓存价 + 输出 × 输出价`，除以一百万。Fast、长上下文、历史价格、缓存写入、其他服务费用与订阅计费会改变结果。[OpenAI 定价](https://developers.openai.com/api/docs/pricing)

## 统计局限

- 只覆盖本机当前存在且能沿父线程关系关联的 34 个会话；删除、远程或其他任务中的工作没有补猜。
- 原始日志包含对话和工具上下文，未上传；公开的只有聚合、前缀 hash、时间范围和复算工具。
- 这是截止点快照，后续开发与本次发布仍会继续消耗 token。
- 用户提示词条数不等于人工投入时长，模型输出条数也不等于正确代码量。
